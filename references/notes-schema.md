# notes.json 结构规范

`render.js` 会做严格校验：`topics[].title`、`items[].text/plain/ts` 缺任何一项都直接报错退出；
`check_notes.js` 会做质量校验：不通过（exit≠0）不许交付。

## 完整结构

```json
{
  "title": "视频标题（可精简，去掉营销前缀）",
  "bvid": "BV1xxxxxxxxx",
  "page": 1,
  "duration": "12:34",
  "up": "UP主名",
  "tldr": "一句话看懂：整条视频最核心的那个判断，40–70 字",
  "coverage": {
    "audio": "官方字幕（中文，带时间戳）/ 本地转写 N 句（语种）",
    "ocr": "关键帧 20 帧，识别出 N 块有效画面文字",
    "missing": ["没有 SESSDATA，走本地转写，专有名词可能有误差"]
  },
  "ads": [{ "t0": "02:10", "t1": "03:05" }],
  "topics": [
    {
      "no": 1,
      "title": "主题名（8–16 字，动词或判断句，不用名词堆砌）",
      "range": "00:00–04:47",
      "summary": "本段一句话结论，30–60 字",
      "items": [
        {
          "title": "小标题：这一条讲什么，≤14 字",
          "mark": "⭐",
          "conf": "✅",
          "ts": "01:32",
          "src": "音频",
          "text": "原话：忠于讲者原意的表述，12–240 字，不压缩成结论",
          "plain": "简易理解：30–140 字，三段式（是什么 / 白话机制或类比 / 关键数字与边界）",
          "note": "可选：补充说明、公式、图表含义、换算",
          "conflict": false,
          "low": false
        }
      ]
    }
  ]
}
```

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 视频标题 |
| `bvid` / `page` | 建议 | 分P 必须填真实页码 |
| `duration` / `up` | 建议 | 展示用 |
| `tldr` | ✅ | 「一句话看懂」，全篇唯一最重要的判断 |
| `coverage.audio` / `coverage.ocr` | ✅ | 采集情况，用户判断可信度靠这个 |
| `coverage.missing` | 有缺失时必填 | 字符串数组，明确说缺什么 |
| `ads[]` | 有则填 | 会渲染成【广告时段，跳过】 |
| `topics[].title` | ✅ | 主题名 |
| `topics[].range` | ✅ | 起止时间戳 `mm:ss–mm:ss` |
| `topics[].summary` | ✅ | 本段小结，渲染为引用块 |
| `items[].title` | ✅ | **小标题**：这条知识点的名字，≤14 字（硬上限 20），同主题内不得重复 |
| `items[].mark` | ✅ | `⭐` / `💡` / `⚠️` |
| `items[].conf` | ✅ | `✅` / `🤔` / `📌` |
| `items[].ts` | ✅ | 该条对应时间点，从 digest 抄 |
| `items[].src` | ✅ | `音频` / `画面` / `交叉印证` |
| `items[].text` | ✅ | **原话**：忠于讲者原意，12–240 字 |
| `items[].plain` | ✅ | **简易理解**：30–140 字（硬上限 160），精简模式不显示但校验必填 |
| `items[].low` | 可选 | `true` 表示次要条目，精简模式下隐藏 |
| `items[].note` | 可选 | 补充说明，渲染为 📎 行 |
| `items[].conflict` | 可选 | `true` 渲染【信息冲突】 |

## 标记语义

- `⭐` 核心知识点：定义、原理、关键结论、重要对比
- `💡` 实操要点：具体怎么做、步骤、工具、配置
- `⚠️` 风险边界：限制条件、坑、失效场景、反例

- `✅` 定论：有数据/有演示支撑的陈述
- `🤔` 个人观点：讲者主观判断、经验之谈
- `📌` 待验证：转写可能有误的专有名词、未给出处的主张

## 分层与编号（渲染器自动生成）

```
内容地图（全篇骨架，表格：主题 / 时间段 / 条数 / 小标题）
  └─ ## 1. 主题      ← 第一层：章节
       └─ ### 1.1    ← 第二层：知识点
            ├─ ▌小标题        ← 第三层：这一条讲什么（≤14 字）
            ├─ 原话：…        ← 方框内，讲者原意（淡粉底）
            ├─ ⏱ 音频时间 …   ← 紧跟原话，方便回看核对
            └─ 简易理解：…    ← 方框内，白话 + 完整（淡蓝底）
```

思维导图大纲用括号树表示记忆顺序：（1）主题 →（1.1）知识点 →（1.1.1）小标题。

正文编号与思维导图大纲严格一一对应，方便对照阅读与复制到幕布/飞书。

## 「原话」怎么写

- **忠于讲者原意**，不是你的总结。原话是「他说了什么」，不是「你认为他想说什么」。
- 允许长（≤240 字）。**不要为了省字把三句话压成一句**——信息丢在压缩里。
- 去掉口头禅和情绪表达（「这个特别牛」「对不对」），但**不要改写论证结构**。
- 时间戳、限定条件（「在……的前提下」）、数字，原话里有的就得有。

## 「简易理解」怎么写（三段式，闸门会验）

简易理解要同时做到两件看起来矛盾的事：**像初中生一样好懂**，并且**把原话讲全了**。写法是固定三段：

1. **是什么**：一句话给出结论，用日常词。
2. **为什么**：用类比或因果白话讲清机制（不是术语解释，是"就像……所以……"）。
3. **边界**：原话里的关键数字、适用条件、例外，**必须保留**。

硬性约束（`check_notes.js` 会拦）：

| 规则 | 判法 | 级别 |
|---|---|---|
| 太短讲不清 | < 15 字 | ❌ 拦 |
| 太长不是"讲明白" | > 160 字 | ❌ 拦 |
| 偏短或偏长 | < 30 或 > 140 字 | ⚠️ 提示 |
| 只是换词重排 | 与原话字符二元组重合度 ≥ 85% | ❌ 拦 |
| 关键数字全丢 | 原话有数字、简易理解一个都没有 | ⚠️ 提示 |
| 凭空造数字 | 简易理解出现原话里没有的数字 | ❌ 拦 |
| 没翻译成人话 | 出现黑话词表 | ❌ 拦 |

**数字保真是「全面」的唯一可判定标准**：原话里的年份、比例、金额、数量，在简易理解里至少要出现一个。
反过来，简易理解里绝不能冒出原话没有的数字——那是幻觉，不是简化。

## 写作红线

1. 时间戳必须来自 `digest.md`，凭空写一个也算编造。
2. `plain` 里出现「赋能、抓手、颗粒度、闭环、对齐」这类词，说明没翻译成人话，重写。
3. 一条只讲一个点。如果一句话里有「而且」「同时」「另外」，拆成两条。
4. 不要复述讲者的口头禅和情绪表达（"这个特别牛"），只留信息。
5. 素材里模糊不清的，宁可标 📌 也不要拍脑袋补全。
6. 简易理解不能只是把原话换几个词——闸门会直接判 FAIL。
